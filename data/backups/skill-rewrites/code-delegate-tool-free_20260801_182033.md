# 代码委派工具免费版

## 概述

---
代码委派工具免费版为个人开发者提供将编程任务委派给本地代码 CLI 执行的能力。工具采用异步流程设计,主 Agent 在委派任务后立即响应用户,保持对话流畅。委派的任务在后台执行,用户下次交互时查看结果.
核心原则:主 Agent 永远不直接写代码,所有编程任务都通过委派执行.
## 核心能力

### 1. 异步委派流程

```text
步骤1 exec 委派命令      → 获取会话 ID
步骤2 立即回复用户       → "正在处理,请稍候"
步骤3 结束当前轮次       → 不再调用工具
步骤4 用户下次消息时     → 检查委派状态
步骤5 完成则返回结果     → 未完成则告知"仍在处理"
```

**处理**: 解析异步委派流程的输入参数,完成核心逻辑,返回结构化响应.
**输出**: 返回异步委派流程的响应数据,包含状态码、结果和日志.
- 执行此能力时使用`input_params`参数,支持创建/查询/导出操作

### 2. 会话上下文保持

| 模式 | 用途 | 参数 |
|---|---|---|
| 新会话 | 新任务、测试验证 | 无需额外参数 |
| 继续会话 | 修复迭代、延续上下文 | `--continue` |

**处理**: 解析会话上下文保持的输入参数,完成核心逻辑,返回结构化响应.
**输出**: 返回会话上下文保持的响应数据,包含状态码、结果和日志.
### 3. 独立测试验证

代码编写完成后,使用全新会话(不带 `--continue`)独立测试:

```text
步骤1 委派编写代码     → 作者会话(可用 --continue 迭代)
步骤2 委派测试代码     → 测试会话(全新,不带 --continue)
```

**处理**: 解析独立测试验证的输入参数,完成核心逻辑,返回结构化响应.
**输出**: 返回独立测试验证的响应数据,包含状态码、结果和日志.

## 错误处理

| 问题分类 | 错误标识 | 根因说明 | 应对策略 |
|:---------|:---------|:---------|:---------|
| 认证问题 | 401 | Key配置错误或已失效 | 重新配置或生成API Key |
| 权限不足 | 403 | 当前Key无访问权限 | 检查账户权限,升级套餐 |
| 频率超限 | 429 | 请求过于频繁 | 实施限速,间隔2秒重试 |
| 输入异常 | 400 | 参数缺失或格式不对 | 逐项校验输入参数 |
| 服务故障 | 500-503 | 服务器内部错误 | 等待恢复后重试,最多2次 |
## 使用场景

### 场景一: 个人项目功能开发

开发者需要实现一个新功能,委派给代码 CLI 执行.
```bash
# 委派任务
请委派以下任务到项目 my-project:
任务: 在 src/auth/ 目录下实现 JWT 认证模块
要求: 包含签发、验证、刷新三个函数
语言: Python
```

委派命令:

```bash
cd "projects/my-project" && claude -p \
  "在 src/auth/ 目录下实现 JWT 认证模块,包含签发、验证、刷新三个函数,使用 Python" \
  --output-format text \
  --max-turns 10
```

### 场景二: Bug 修复与迭代

用户报告 Bug,委派修复并迭代验证.
```bash
# 委派修复(使用 continue 延续上下文)
请委派修复以下 Bug:
项目: projects/web-app
问题: WebSocket 连接存在内存泄漏
使用 continue 模式延续上次会话上下文
```

### 场景三: 独立代码测试

代码编写完成后,用全新会话独立测试.
```bash
# 委派测试(全新会话)
请委派测试以下项目:
项目: projects/my-project
任务: 运行测试套件,报告通过/失败结果
注意: 使用全新会话,不带 continue
```

## 优选实践

### 1. 任务描述清晰

好的任务描述应包含:

| 要素 | 说明 | 示例 |
|:------|------:|:------|
| 目标 | 做什么,改哪个文件 | "实现 src/auth/login.py" |
| 上下文 | 函数名、错误信息、期望行为 | "修复 verify_token 函数的过期检查" |
| 约束 | 语言、框架、代码风格 | "使用 Python,遵循 PEP 8" |
| 单一性 | 一次一个任务 | 不要在一个任务中混合多个功能 |

### 2. 安全优选实践

| 规则 | 说明 |
|---:|:---|
| 隔离项目目录 | 永远在专用 projects/ 目录运行 |
| 限制项目范围 | cd 前缀确保在正确目录操作 |
| 审查委派输出 | 始终通过主 Agent 转达结果 |
| 禁用危险参数 | 不使用 --dangerously-skip-permissions |

### 3. 失败处理原则

```text
如果委派失败或超时,主 Agent 不直接写代码.
告诉用户:"编程任务未完成,要再试一次吗?"
用更长超时或更简单的任务描述重试.
```

## 常见问题

### Q1: 使用本技能需要什么前置条件?
A: 需要配置对应API Key并确保运行环境满足依赖说明中的要求。首次使用请参考快速开始章节。

### Q2: 遇到API调用失败怎么办?
A: 检查API Key是否正确配置、网络连接是否正常。如遇429限流,等待2秒后重试,最多3次。

### Q3: 支持哪些输入格式?
A: 支持文本输入和JSON格式参数。具体格式参考输入格式章节的参数说明表。

### Q4: 如何处理超时或无响应?
A: 默认超时30秒。超时后检查网络连接和API服务状态,确认服务正常后重试。

### Q5: 输出结果不完整怎么办?
A: 检查输入参数是否完整,确认prompt描述清晰具体。对于长文本输入,尝试分段处理。
