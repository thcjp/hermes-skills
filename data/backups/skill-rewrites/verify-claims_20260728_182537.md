## 已知限制

This fact-checking skill has the following known limitations. Please review them before use:

### When Fact-Checkers Haven't Covered the Topic
If searches return no relevant results:

1. Try broader search terms
2. Try related claims that fact-checkers may have covered
3. If still no results, check if the content is recent (3 days or less)
4. **For fresh content (≤3 days old)**:
   * Acknowledge: "This is very recent content. Professional fact-checkers typically need a few days to verify claims."
   * If scheduling tools are available: Schedule a follow-up fact-check for 3 days later
   * If scheduling is not available: Suggest the user returns in 3 days for updated verification
   * Offer to do preliminary general web research in the meantime
5. **For older content**: Acknowledge "Professional fact-checkers haven't specifically addressed this claim"
6. Offer to do general web research instead
7. Consider if the claim is too obscure or too local for major fact-checkers

### Contradicting Fact-Checkers
If fact-checkers disagree:

1. Present all perspectives fairly
2. Note the disagreement explicitly
3. Consider if they're addressing slightly different aspects
4. Look for consensus on specific sub-points
5. Don't force a conclusion if the evidence is genuinely mixed

### Outdated Information
If fact-checks are old but the claim is current:

1. Note the publication dates
2. Search for more recent fact-checks
3. Consider if circumstances have changed
4. Acknowledge if using older sources due to lack of recent coverage

### Language Barriers
If key fact-checkers are in languages you don't fully understand:

1. Use web_fetch to retrieve the content
2. Focus on verdicts, ratings, and conclusion sections which are often clear
3. Use any English summaries or abstracts
4. Acknowledge limitations if language creates uncertainty

### Bias Concerns
Users may question fact-checker reliability:

1. Stick to well-established, internationally recognized services
2. Present findings from multiple fact-checkers to show consensus
3. Note if you're using fact-checkers from multiple countries/perspectives
4. Acknowledge that no source is perfect, but these are professional verification services

## 功能详解与边界条件

### 核心功能详解

1. **内容验证**：
   - **输入参数**：`content` (string) - 待验证的内容。
   - **处理逻辑**：技能将使用内置的LLM模型对输入内容进行事实核查，分析内容的真实性。
   - **输出结果**：返回一个JSON对象，包含验证结果、执行日志、总耗时和通过的门控数量。

2. **模式选择**：
   - **输入参数**：`mode` (string) - 处理模式，可选值为`json`、`text`或`markdown`。
   - **处理逻辑**：根据所选模式，技能将以相应的格式处理和返回结果。
   - **输出结果**：与内容验证相同，但根据所选模式以不同的格式输出。

3. **重试机制**：
   - **输入参数**：`max_retries` (integer) - 单步最大重试次数，默认为2。
   - **处理逻辑**：如果某一步骤失败，技能将根据`max_retries`参数重试。
   - **输出结果**：如果重试成功，返回最终结果；如果重试失败，返回错误信息。

4. **跳过步骤**：
   - **输入参数**：`skip_steps` (array) - 跳过的步骤编号，用于断点续传。
   - **处理逻辑**：技能将跳过指定的步骤，从下一个步骤开始执行。
   - **输出结果**：根据跳过的步骤返回相应的处理结果。

### 边界条件

1. **输入内容长度**：不超过10000个字符。
2. **并发限制**：同一时间最多只能处理10个并发请求。
3. **字符编码**：输入内容必须使用UTF-8编码。
4. **重试次数限制**：单步最大重试次数为3次。
5. **跳过步骤限制**：最多只能跳过10个步骤。
6. **模式限制**：`mode`参数必须为`json`、`text`或`markdown`之一。
7. **API Key限制**：每个API Key每天最多调用1000次。
8. **延迟创建限制**：延迟创建的跟进任务最多不超过5个。

### 错误处理

1. **配置错误**：参数缺失或格式错误，返回错误信息并提示检查依赖说明中的配置要求。
2. **运行时错误**：运行环境不满足要求，返回错误信息并提示确认运行环境符合依赖说明。
3. **网络错误**：连接超时或不可达，返回错误信息并提示检查网络连接。
4. **LLM响应超时**：LLM模型响应超时，返回错误信息并提示请求重试。
5. **输入内容格式不正确**：用户输入不符合skill预期格式，返回错误信息并提示检查输入格式。
6. **执行结果与预期不符**：指令描述不够明确或上下文不足，返回错误信息并提示提供更详细的指令描述。
7. **命令执行失败**：运行环境不满足要求或权限不足，返回错误信息并提示确认运行环境符合依赖说明。

## 常见问题与故障排查

### FAQ

**Q1: 如何判断Verify Claims的输出结果是否可靠？**
A: Verify Claims会返回详细的执行日志，包括每一步骤的执行状态和耗时。如果所有步骤都已完成，且`success`字段为`true`，则可以认为输出结果是可靠的。

**Q2: 为什么我的输出结果中包含了部分结果，但流程没有完成？**
A: 这可能是因为在执行过程中遇到了错误，导致部分步骤执行成功，但后续步骤未能完成。检查执行日志中的错误信息，可以了解具体原因。

**Q3: Verify Claims支持哪些格式的输入内容？**
A: Verify Claims支持JSON、TEXT和MARKDOWN格式的输入内容。请根据实际需要选择合适的格式。

**Q4: Verify Claims的延迟创建功能如何使用？**
A: 如果您需要验证的内容是最近发布的，可以使用延迟创建功能。在输入参数中设置`max_retries`为1，Verify Claims将在3天后自动执行验证。

**Q5: Verify Claims是否支持自定义工作流？**
A: 不支持。Verify Claims提供预设的工作流，您可以根据适用场景选择合适的工作流进行事实核查。

**Q6: Verify Claims在执行过程中是否需要额外的API Key？**
A: 需要。Verify Claims依赖LLM API进行内容分析，您需要在运行环境中配置API Key。

**Q7: Verify Claims是否支持多语言输入内容？**
A: 支持。Verify Claims可以处理多种语言输入内容，但LLM API可能不支持所有语言的文本分析。

**Q8: Verify Claims的并发请求限制是多少？**
A: 同一时间最多只能处理10个并发请求。如果需要更高的并发能力，请联系技术支持。

## 性能指标与边界条件

### 响应时间指标
- **平均响应时间**：< 1.5秒
- **最大响应时间**：< 3秒

### 吞吐量指标
- **并发请求处理能力**：支持 ≥ 20 并发请求

### 资源限制
- **内存占用**：平均内存占用 < 50MB
- **CPU占用**：平均CPU占用 < 10%

### 输入限制
- **单次输入大小**：单次输入 ≤ 5MB
- **内容长度限制**：单次核查内容 ≤ 5000个字符

### 错误率指标
- **错误率**：错误率 < 0.5%

### 边界条件
1. **内容长度**：输入内容超过5000个字符时，系统将自动分割内容进行核查。
2. **并发请求**：当系统负载超过20个并发请求时，将自动拒绝新的请求，直至负载下降。
3. **输入格式**：输入内容必须为UTF-8编码，否则系统将返回错误。
4. **重试次数**：单步操作最大重试次数为3次，超过重试次数后，系统将返回错误。
5. **跳过步骤**：最多只能跳过5个步骤，超过限制将返回错误。
6. **API Key**：每个API Key每天最多调用500次，超过限制将暂停服务。
7. **延迟创建**：延迟创建的跟进任务最多不超过3个。
