# 精英长记忆（基础版）

### 解决AI Agent跨会话遗忘问题

精英长记忆基础版是专为AI Agent设计的长期记忆系统，它通过WAL防丢失和热内存技术，确保AI Agent在跨会话中不会丢失上下文，从而解决跨会话遗忘的核心痛点。

### 核心特性

- **WAL写前日志防丢失**：采用"先写状态，再回复用户"模式，在系统崩溃或意外关闭时，保证上下文不丢失。
- **热内存文件**：通过SESSION-STATE.md文件记录当前任务、关键上下文、待办动作、近期决策，实现快速状态恢复。
- **基础关键词检索**：自动召回相关历史记忆，简化记忆检索过程。
- **自动会话管理**：会话开始自动加载记忆，会话结束时自动更新和归档。

### 核心能力

#### WAL写前日志防丢失

- **工作原理**：在用户表达偏好、做出决策、给出期限或纠正错误时，先写入SESSION-STATE.md文件，再回复用户。
- **触发时机**：用户表达偏好、做出决策、给出期限、纠正错误。
- **性能**：写入本地文件是毫秒级操作，对用户感知无影响。

#### 热内存文件

- **文件内容**：当前任务、关键上下文、待办动作、近期决策。
- **格式**：Markdown，人类可读可编辑。
- **加载**：会话开始立即加载。
- **归档**：重要内容定期迁移到MEMORY.md长期归档。

#### 会话管理

- **会话开始**：读取SESSION-STATE.md文件。
- **会话结束**：更新SESSION-STATE.md文件，创建memory/YYYY-MM-DD.md日志记录当日活动。

### 使用流程

1. **创建热内存文件**：在工作区根目录创建SESSION-STATE.md文件，包含当前任务、关键上下文、待办动作、近期决策四个区块。
2. **执行WAL协议**：遵循"先写后回复"原则，确保关键信息被记录。
3. **会话管理与归档**：会话结束时自动更新和归档。

### 错误处理

- **全部遗忘**：会话开始未读取SESSION-STATE.md文件，热内存未加载。
- **记忆文件未加载**：Agent跳过读取记忆步骤，直接开始对话。
- **重复犯错**：教训未记录到SESSION-STATE.md文件，新会话无法召回。

### 示例

#### 跨会话技术决策延续

**输入**：

- 会话A（周一）：用户说"数据库用MySQL，开发环境用SQLite"
- 会话B（周三，新会话）：用户说"部署脚本怎么写？"

**执行**：

1. 会话A执行WAL：写入SESSION-STATE.md"决策：MySQL生产/SQLite开发"
2. 会话B会话开始：读取SESSION-STATE.md → 召回MySQL决策 → 回复时主动考虑MySQL部署配置

**输出**：

```markdown
# SESSION-STATE.md 更新内容
## 近期决策(续1)
- 2026-07-21: 数据库选型 MySQL生产环境/SQLite开发环境
# ...
# 会话B回复
基于SESSION-STATE.md中的MySQL决策，生成MySQL部署脚本：
- 连接池配置（max_connections=100）
- 字符集设置（utf8mb4）
- 时区配置（UTC+8）
```

### FAQ

**Q1：WAL协议会不会拖慢回复速度？**

A：写入本地文件是毫秒级操作，对用户感知无影响。相比崩溃后丢失上下文的代价，这点延迟完全值得。

**Q2：基础版支持向量检索吗？**

A：基础版不支持向量语义检索，仅支持SESSION-STATE.md热内存加载与关键词匹配。

**Q3：基础版有成本预算控制吗？**

A：基础版不支持成本预算控制与自动降级。

### 已知限制

1. **无向量语义检索**：基础版仅支持SESSION-STATE.md热内存加载，无法进行语义相似召回。
2. **无混合检索**：不支持向量+关键词+图谱三路混合检索与RRF融合排序。
3. **无成本预算控制**：不支持日/月预算上限配置与自动降级机制。
4. **无记忆卫生自动化**：不支持自动去重、衰减、晋升、降级、归档、删除六项维护。
