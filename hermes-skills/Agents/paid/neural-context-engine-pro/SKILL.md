### 2. 扩散激活检索（基础+深度）
```text
查询："为什么上周部署失败？"
深度1（基础）：找到直接相关的部署记忆
深度2（专业）：沿CAUSED_BY突触追踪根因

扩散过程：
1. 激活"部署失败"神经元
2. 沿CAUSED_BY突触扩散 → "数据库连接超时"
3. 继续扩散 → "连接池配置过小"
4. 沿LEADS_TO突触 → "调整配置后解决"
结果：完整因果链：部署失败 ← 数据库超时 ← 连接池过小 → 调整解决
```

## 使用场景
### 场景一：多项目并行记忆管理（独立开发者角色）
**场景描述**：独立开发者同时进行3个项目，需要为每个项目维护独立记忆上下文，避免跨项目混淆.
**配置**：
```bash
nmem create-brain --name project-a
nmem create-brain --name project-b
nmem create-brain --name project-c
nmem switch-brain --name project-a
nmem_remember(
  content="项目A使用React + TypeScript",
  type="decision",
  tags=["frontend", "tech-stack"],
  priority=8
)
```
**效果**：3个项目记忆完全隔离，切换成本从5分钟降至0。跨项目不会混淆上下文.
### 场景二：团队知识共享（技术负责人角色）
**场景描述**：技术负责人希望将一个项目的优选实践与踩坑经验共享到其他项目，避免重复踩坑.
**操作流程**：
```bash
nmem transplant \
  --from project-a \
  --to project-b \
  --filter-tags best-practice,lesson-learned \
  --deduplicate
nmem_recall query="优选实践" --brain project-b
```
**效果**：项目B立即获得项目A的优选实践，避免重复踩坑，团队学习效率提升50%.
### 场景三：长期项目知识沉淀（架构师角色）
**场景描述**：为期6个月的项目需要将所有技术决策、架构讨论、踩坑经验沉淀为可检索的知识库，支持因果链追溯.
**操作流程**：
```bash
nmem snapshot --name "milestone-1"

  query="为什么选择微服务架构",

```
**效果**：6个月项目的所有决策可追溯，因果链完整，架构决策原因可一键检索.

**场景描述**：运维工程师发现自己重复执行相同的故障处理流程，希望识别工作流模式并自动化.

### 场景五：冲突决策识别（产品经理角色）

## 性能优化策略
### 多脑管理优化
1. **脑大小控制**：单个脑建议不超过10万条记忆，过大时拆分
2. **自动切换优化**：配置上下文关键词，提升自动切换准确率
3. **脑索引优化**：定期重建脑索引，提升检索速度
4. **冷脑归档**：不活跃的脑归档压缩，节省存储
### 深度检索优化
1. **深度按需选择**：日常用depth=1，复杂问题用depth=3
2. **超时控制**：depth=3设置500ms超时，避免长时间阻塞
3. **结果缓存**：相同查询缓存结果，避免重复检索
4. **并行检索**：多个查询并行执行，提升吞吐
### 快照管理优化
1. **增量快照**：仅快照变更部分，节省存储与时间
2. **快照压缩**：旧快照自动压缩归档
3. **快照保留策略**：保留最近30个快照，自动清理旧快照
4. **快照验证**：定期验证快照完整性
### 自动提取优化
1. **置信度调优**：调整提取置信度阈值，平衡召回与精确
2. **类别过滤**：仅提取特定类别，过滤噪音
3. **批量处理**：大量对话批量提取，减少API调用
4. **去重策略**：启用自动去重，避免重复记忆
### 成本控制
- 深度检索按需使用：日常depth=1，复杂问题depth=3
- 自动提取阈值调优：避免提取低价值信息
- 快照定期清理：避免存储膨胀
- 冷脑归档：不活跃脑压缩存储
