## 使用场景
### 场景一：企业级长期项目协作记忆（技术负责人角色）
**痛点**：3个月的项目，团队成员轮流与Agent协作，Agent记不住上一位成员的决策与偏好，导致重复沟通.
**配置**：
```text
~/evolve-loop/
├── memory.md                    # 团队全局规范
├── projects/
│   └── enterprise-app/
│       ├── memory.md            # 项目架构决策
│       ├── corrections.md       # 项目纠正历史
│       ├── decisions.md         # 项目决策记录
│       └── metrics/             # 项目改进度量
├── snapshots/                   # 决策快照
└── .cloud-config.json           # 团队共享配置
```
**Agent行为**：
- 每位团队成员会话开始时，云同步拉取最新团队记忆
- 团队成员A的纠正自动同步到成员B的Agent
- 重大架构决策前自动创建快照
- 每周生成DMAIC改进报告，量化团队进化效果
- 多项目并行：同时管理3个项目，零上下文污染
**效果**：团队协作效率提升约40%，重复沟通减少约70%，改进效果可量化呈现给管理层.

## 性能优化策略
### 多项目并行优化
1. **项目索引缓存**：维护项目ID到记忆文件的映射缓存，O(1)查找
2. **懒加载**：仅加载当前活跃项目的HOT，其他项目按需加载
3. **预取策略**：根据用户行为模式预取可能切换的项目记忆
4. **分区存储**：按项目分区存储，避免全量扫描
### 云同步优化
1. **增量同步**：仅传输变更部分，非全量同步，节省90%带宽
2. **压缩传输**：同步数据启用gzip压缩，减少70%传输量
3. **批量推送**：小变更聚合后批量推送，减少网络往返
4. **冲突解决**：自动合并策略，减少90%手动干预
### 度量采集优化
1. **异步采集**：度量数据异步写入，不阻塞主流程
2. **采样策略**：高频指标采样而非全量记录，降低开销
3. **聚合计算**：原始数据按时间窗口聚合，减少存储
4. **冷热分离**：近期度量热存储，历史度量冷归档
### 成本控制
- 低重要性记忆使用本地存储，不同步至云端
- 度量采集设置采样率，避免全量记录
- 云同步限制频率（默认5分钟），避免过度同步
- 快照按需创建，自动清理过期快照
