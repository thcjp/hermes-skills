### 2. 并行任务调度（专业版独有）
独立任务并行执行，提升开发速度：
```bash
swarm schedule analyze --plan docs/plans/feature-plan.md
swarm schedule execute --max-parallel 3
```
**调度特性**：
- 依赖图分析：自动识别任务间依赖关系
- 并行分组：无依赖的任务自动并行执行
- 负载均衡：round-robin / weighted两种策略
- 冲突检测：检测文件级冲突，避免并行修改
**处理**: 解析并行任务调度（专业版独有）的输入参数,完成核心逻辑,返回结构化响应.
**输出**: 返回并行任务调度（专业版独有）的响应数据,包含状态码、结果和日志.
### 3. 成本预估与控制（专业版独有）
实时监控Token消耗，避免超预算：
```bash
swarm cost estimate --plan docs/plans/feature-plan.md
swarm cost realtime
swarm cost alert --threshold 0.8
```
**成本控制特性**：
- Token预算：设置总预算与每任务预算
- 实时监控：每任务消耗实时追踪

**处理**: 解析成本预估与控制（专业版独有）的输入参数,完成核心逻辑,返回结构化响应.
**输出**: 返回成本预估与控制（专业版独有）的响应数据,包含状态码、结果和日志.
### 4. 多层review（专业版独有）
五层review流水线，全面保证代码质量：
| 层级 | 审查内容 | 严重度阈值 | 修复循环 |
|---:|---:|---:|---:|
| 1. 规范合规 | 是否符合规范要求 | 任何不合规 | 实现→修复→重审 |
| 2. 代码质量 | 可读性/测试/错误处理 | Important+ | 实现→修复→重审 |
| 3. 架构一致性 | 模块边界/依赖/模式 | 任何架构异味 | 实现→修复→重审 |
| 4. 安全性 | 注入/认证/敏感信息 | 任何高危漏洞 | 实现→修复→重审 |
| 5. 性能 | 复杂度/查询/内存 | 🔴需优化 | 实现→修复→重审 |
**执行顺序**：1→2→3→4→5，每层通过后才进入下一层。Critical问题立即停止.
**处理**: 解析多层review（专业版独有）的输入参数,完成核心逻辑,返回结构化响应.
**输出**: 返回多层review（专业版独有）的响应数据,包含状态码、结果和日志.
### 5. 自动修复循环（专业版独有）
失败自动重试，避免手动干预：
```text
自动修复流程：
1. review发现问题
2. 自动分派修复子代理（同一实现者）
3. 修复策略选择：
   - refactor：重构问题代码
   - simplify：简化复杂逻辑
   - add-test：补充测试覆盖
   - add-validation：添加输入验证
4. 重新review
5. 循环直到通过或达到最大次数（3次）
熔断机制：
- 同一问题修复3次未通过 → 熔断
- 熔断后冷却5分钟
- 冷却后降级为手动修复
```
**处理**: 解析自动修复循环（专业版独有）的输入参数,完成核心逻辑,返回结构化响应.
**输出**: 返回自动修复循环（专业版独有）的响应数据,包含状态码、结果和日志.

### 7. 失败回滚（专业版独有）
任务失败自动回滚，保护已完成工作：
```bash
swarm checkpoint create --label "任务3开始前"
swarm rollback auto --on-failure
swarm rollback to --checkpoint "任务3开始前" --confirm
swarm rollback idempotency-check --task task-3
```
**回滚特性**：
- 自动回滚：任务失败时自动回滚至上一检查点
- 检查点：每任务开始前自动创建
- 幂等保证：回滚后可安全重试
- 策略选择：git-revert / git-reset / 自定义
**处理**: 解析失败回滚（专业版独有）的输入参数,完成核心逻辑,返回结构化响应.

**效果**：开发时间从3天缩短至1天，效率提升约3倍.
### 场景二：成本敏感型开发预算控制（项目经理角色）
**痛点**：开发预算有限，担心Agent调用超支，无法实时掌控消耗.
**使用方式**：
```bash
swarm cost budget --total 500000 --per-task 50000
swarm cost realtime
swarm cost hard-stop --threshold 0.9
```
**效果**：开发成本可视可控，超支风险降低约90%.
### 场景三：高安全要求项目的多层审查（安全工程师角色）
**痛点**：金融项目要求代码必须通过安全审查，但传统流程安全审查在最后，发现问题修复成本高.
**使用方式**：
```text
[五层review流水线]
任务实现 → 规范✓ → 质量✓ → 架构✓ → 安全审查
安全审查发现：
- 🔴 高危：SQL注入风险（user-input未参数化）
- 🟡 注意：密码强度校验缺失
[自动修复]
- 添加参数化查询
- 添加密码强度校验
[重新安全审查]
✅ 安全等级：🟢安全
[继续性能review]
```

## 性能优化策略
### 并行调度优化
1. **依赖图缓存**：依赖分析结果缓存，避免重复计算
2. **智能分组**：基于任务相似性分组，提升缓存命中率
3. **负载预测**：基于历史数据预测任务耗时，优化调度
4. **冲突避免**：文件级冲突检测，避免并行修改
### 成本控制优化
1. **上下文压缩**：智能压缩任务上下文，减少Token消耗
2. **review分层**：低风险任务跳过架构/安全review
3. **缓存复用**：相似任务的review结果复用
4. **模型路由**：简单任务用GPT-4o-mini，复杂任务用GPT-4o
### 多层review优化
1. **并行review**：架构/安全/性能review可并行（无依赖时）
2. **增量review**：仅review变更部分，非全量
3. **提前终止**：Critical问题立即终止，不继续后续review
4. **结果缓存**：相同代码的review结果缓存
### 失败回滚优化
1. **增量检查点**：仅保存变更部分，非全量快照
2. **幂等设计**：任务设计为幂等，可安全重试
3. **快速回滚**：git-revert策略，秒级回滚
4. **状态清理**：回滚后自动清理部分完成的状态
### 成本控制
- 并行任务数限制（默认max=5），避免资源过度消耗
- review层按需启用（低风险任务跳过架构/安全review）
- 自动修复循环限制（默认max=3），避免无限循环
- 检查点按需创建（每任务开始前），避免存储浪费
