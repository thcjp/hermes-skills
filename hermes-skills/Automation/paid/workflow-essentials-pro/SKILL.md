## 核心能力
### Step 1：识别自动化机会
**自动化黄金法则**：每周重复两次以上、不需要创造性思维的任务，都值得自动化.
**适合自动化的四特征**：
| 特征 | 说明 | 示例 |
|:-----|:-----|:-----|
| 重复性 | 每次步骤相同 | 每周格式相同的周报 |
| 规则性 | 规则驱动，无需判断 | 付款后创建发票 |
| 高频率 | 每日或每周执行 | 表单数据入库 |
| 耗时长 | 单次10分钟以上 | 数据手动汇总 |
**快速识别清单**：
```text
问自己：
  □ 这个任务每次步骤都一样吗？
  □ 这个任务每周至少做两次吗？
  □ 单次耗时超过10分钟吗？
  □ 不需要创造性判断吗？
四个都"是" → 立即自动化
三个"是" → 建议自动化
两个以下"是" → 手动即可
```
**时间成本计算**：
```text
时间成本 = (单次耗时分钟 × 月频率) / 60
示例：15分钟的任务 × 每月20次 = 每月5小时
按时间成本从高到低排序，优先自动化成本最高的任务.
```
**处理**: 解析Step 1：识别自动化机会的输入参数,完成核心逻辑,返回结构化响应.
**输出**: 返回Step 1：识别自动化机会的响应数据,包含状态码、结果和日志.
### Step 2：设计自动化方案
#
### 六种设计模式 — 专业版独有
每种模式都是一个可复用的设计模板，根据任务特征选择合适的模式.
**模式1：定期汇总**
```text
特征：多个数据源 → 合并 → 统一报告
触发：定时
适用：周报、月报、数据汇总
模板：
  触发：定时（如每周五）
  步骤1：从多个源收集数据
  步骤2：合并整理
  步骤3：生成报告
  步骤4：发送/保存
  错误处理：失败通知，跳过缺失源继续处理
```
**模式2：数据同步**
```text
特征：系统A → 转换 → 系统B
触发：定时或事件
适用：CRM↔ERP同步、跨工具数据流转
模板：
  触发：定时或新数据事件
  步骤1：从源系统读取数据
  步骤2：按映射规则转换格式
  步骤3：写入目标系统
  错误处理：失败重试3次，记录同步日志
```
**模式3：事件驱动**
```text
特征：事件发生 → 判断 → 响应
触发：事件（Webhook/文件变化/状态变更）
适用：订单处理、告警通知、客户跟进
模板：
  触发：事件发生
  条件：判断事件是否满足响应条件
  步骤1：执行响应操作
  步骤2：发送通知
  错误处理：失败告警，确保不遗漏关键事件
```
**模式4：批量转换**
```text
特征：多个文件 → 统一处理 → 输出
触发：手动或文件监控
适用：格式转换、数据清洗、批量生成
模板：
  触发：手动或目录有新文件
  步骤1：枚举所有待处理文件
  步骤2：逐个执行转换
  步骤3：输出到目标目录
  错误处理：单文件失败跳过，记录错误列表
```
**模式5：流程编排**
```text
特征：多步骤任务 → 按序执行 → 确认完成
触发：事件或手动
适用：审批流程、入驻流程、发布流程
模板：
  触发：流程启动事件
  步骤1-N：按序执行各步骤
  检查点：每步完成后确认，失败则暂停
  完成：所有步骤完成后发送通知
  错误处理：失败暂停流程，通知人工介入
```
**模式6：增量处理**
```text
特征：只处理新增/变更数据
触发：定时
适用：日志分析、数据同步、状态更新
模板：
  触发：定时
  步骤1：记录上次处理位置（水位线）
  步骤2：只读取水位线之后的新数据
  步骤3：处理新数据
  步骤4：更新水位线
  错误处理：失败不更新水位线，下次重试
```
**模式选择速查卡**：
| 任务特征 | 推荐模式 | 典型场景 |
|---:|---:|---:|
| 多源数据合并成报告 | 定期汇总 | 周报、月报 |
| 两个系统间数据流转 | 数据同步 | CRM↔ERP |
| 事件发生后需要响应 | 事件驱动 | 订单处理 |
| 多个文件统一处理 | 批量转换 | 格式转换 |
| 多步骤按序执行 | 流程编排 | 入驻流程 |
| 只处理新增数据 | 增量处理 | 日志分析 |

**三条设计原则**：
1. **从简单开始**：先做2-3步，跑通后再加复杂度
2. **逐步测试**：每步单独测试成功后再串联
3. **必加错误通知**：出问题要能知道，否则静默失败
**处理**: 解析Step 2：设计自动化方案的输入参数,完成核心逻辑,返回结构化响应.

### Step 3：构建与验证
**工具选择速查**：
| 工具 | 适合 | 价格 | 难度 | 能力 |
|:---:|:---:|:---:|:---:|:---:|
| Zapier | 简单2-3步工作流 | $20-50/月 | 简单 | 低-中 |
| Make | 可视化多步骤工作流 | $9-30/月 | 中等 | 中-高 |
| n8n | 复杂工作流，自托管 | 免费或$20/月 | 较难 | 高 |
**构建步骤（通用流程）**：
1. 选择触发器应用
2. 连接账户（OAuth认证）
3. 测试触发器（确认数据能过来）
4. 添加领先个操作
5. 映射字段（匹配数据到目标）
6. 测试操作（确认结果正确）
7. 重复添加更多操作
8. 开启工作流
**验证清单**：
- [ ] 提交测试数据，触发器是否响应
- [ ] 每个操作是否正确执行
- [ ] 数据是否映射到正确字段
- [ ] 边界情况测试（空字段、特殊字符）
- [ ] 错误处理测试（故意制造失败）
**常见问题速修**：
| 问题 | 修复方法 |
|:------|------:|
| 工作流不触发 | 检查触发条件，放宽过滤 |
| 操作失败 | 检查API限流，添加延迟 |
| 数据错误 | 检查字段映射是否正确 |
| 重复执行 | 基于唯一ID去重 |
**处理**: 解析Step 3：构建与验证的输入参数,完成核心逻辑,返回结构化响应.
**输出**: 返回Step 3：构建与验证的响应数据,包含状态码、结果和日志.
### Step 4：维护策略 — 专业版独有
自动化不是"设置完就忘了"。系统化的维护是持续有效的关键.
**维护节奏**：
| 频率 | 时间 | 检查内容 |
|---:|:---|---:|
| 每周 | 5分钟 | 扫描日志，处理失败 |
| 每月 | 15分钟 | 审计所有工作流，淘汰低效的 |
| 每季 | 30分钟 | 评估ROI，优化高效工作流 |
**每周检查清单**：
- 扫描工作流日志，检查是否有错误
- 立即处理任何失败
- 记录本周新增的工作流
**月度审计清单**：
- 审查所有活跃的工作流
- 检查：还在用吗？还在节省时间吗？
- 禁用或删除不用的工作流
- 更新依赖已切换工具的工作流
**文档管理**：
为每个工作流创建文档，包含：
```text
工作流名称：__________
创建日期：__________
最后检查：__________
状态：__________
本月运行次数：____
本月失败次数：____
连接的应用：
  - __________（触发器）
  - __________（操作1）
  - __________（操作2）
排障指南：
  1. 如果不触发：__________
  2. 如果操作失败：__________
  3. 如果数据错误：__________
```
**错误通知集中化**：
- 将所有工作流的错误通知路由到一个地方（Slack频道/邮件/任务管理器）
- 设置："如果任何工作流失败，发消息到[错误频道]"
- 每周审查错误并修复根本原因
**处理**: 解析Step 4：维护策略 — 专业版独有的输入参数,完成核心逻辑,返回结构化响应.
**输出**: 返回Step 4：维护策略 — 专业版独有的响应数据,包含状态码、结果和日志.

### Step 6：持续优化 — 专业版独有
**ROI计算**：
